MAX + n8n — Report СЭМД (v6)

Назначение
----------
Установка n8n 2.42.6, MAX community node 1.1.2 и workflow «Report СЭМД»
для медицинских организаций с одинаковой структурой SQL-базы МИС.
Между организациями меняются домен n8n, адрес и порт SQL Server, имя БД,
SQL-учётная запись и MAX-токен.

До установки
------------
1. Ubuntu Server 22.04.
2. DNS A-запись домена n8n на публичный IP.
3. Прямой NAT TCP 80/443 на сервер n8n.
4. Доступ сервера к SQL Server по TCP 1433 или заданному порту.
5. SQL-логин с минимально необходимыми правами чтения; не использовать sa.
6. Токен MAX-бота.
7. Структура БД должна совпадать с исходным проектом.

Установка
---------
1. Скопировать папку MAX-n8n-install-v6 на Ubuntu.
2. Перейти в каталог пакета.
3. Запустить: sudo bash install.sh
4. Ответить на вопросы установщика. Пароль SQL и токен MAX вводятся скрыто.
5. Установщик проверит DNS и TCP SQL, создаст .env с правами 600,
   индивидуальный N8N_ENCRYPTION_KEY, установит Docker, n8n, Nginx и HTTPS.
6. Открыть HTTPS-домен и создать первую учётную запись Owner.
7. В n8n открыть Settings → n8n API → Create an API key.
8. Ввести API Key в скрытый запрос терминала. Остальная настройка выполняется
   автоматически.

Повторный запуск
----------------
Если найден .env, установщик предложит использовать сохранённые параметры.
Пустой ввод сохраняет прежнее значение. Существующий N8N_ENCRYPTION_KEY
сохраняется. Не удалять и не менять его для действующей установки.
Совпадающие Credentials обновляются при повторной настройке.

TLS SQL Server
--------------
TLS включён по умолчанию. Разрешение недоверенного/самоподписанного
сертификата возможно отдельно, но ослабляет проверку сервера. Если SQL
Server не использует TLS, выберите false. Согласуйте настройку с DBA.

Режим общего отчёта
-------------------
none — общий отчёт не отправляется, персональные уведомления работают.
chat — общий отчёт в групповой чат MAX; нужен ID чата.
user — общий отчёт ответственному пользователю MAX; нужен ID пользователя.
Если ID не указан, общий отчёт отключается.

После установки
---------------
1. Открыть n8n → Data tables → report_recipients.
2. Заполнить только колонку fio ФИО врачей в формате отправки боту.
3. Сотрудник запускает MAX-бота и отправляет ФИО.
4. Workflow сопоставляет ФИО и записывает max_user_id автоматически.
5. Проверить регистрацию сотрудника и отчёты в 09:00 (за предыдущий день)
   и 15:00 (за текущий день).

Безопасность и резервное копирование
------------------------------------
.env содержит SQL-пароль и MAX-токен; хранить защищённо.
Сохранить N8N_ENCRYPTION_KEY: без него Credentials не восстановить.
Делать резервные копии Docker volume n8n_data. Не удалять этот volume.

Ограничения
-----------
DNS и TCP-проверка не подтверждают SQL-аутентификацию, права SELECT
и совпадение структуры БД. До массового запуска проверить SQL-выборки,
оба расписания, индивидуальные уведомления, регистрацию MAX user_id,
режим общего отчёта и повторный запуск установщика.

Сервер рассчитан на прямой NAT 80/443 на n8n. Существующий внешний
reverse proxy требует отдельной адаптации.
