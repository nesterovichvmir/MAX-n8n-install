# MAX + n8n — автоматические отчёты СЭМД (v6)

Установочный комплект для медицинских организаций с одинаковой структурой SQL-базы МИС.

## Назначение

Пакет устанавливает n8n 2.42.6, MAX community node 1.1.2 и workflow **Report СЭМД**. Между организациями меняются домен n8n, адрес и порт SQL Server, имя базы, SQL-учётная запись и токен MAX.

Предполагается полное совпадение схемы БД, таблиц, имён и типов столбцов, используемых SQL-запросами workflow.

## Требования до установки

1. Ubuntu Server 22.04 (рекомендуется отдельная виртуальная машина).
2. DNS A-запись домена n8n, указывающая на публичный IP организации.
3. Входящие TCP-порты 80 и 443 на сервер n8n; исходящий TCP 443.
4. Прямой NAT/проброс TCP 80 и 443 с публичного адреса маршрутизатора на этот сервер.
5. Сетевой доступ сервера n8n к SQL Server по TCP 1433 либо указанному порту.
6. SQL-логин с минимально необходимыми правами чтения. Не использовать `sa`.
7. Токен MAX-бота организации.
8. Совпадающая с исходным проектом структура базы МИС.

## Установка

1. Скопируйте папку `MAX-n8n-install-v6` на Ubuntu Server.
2. Перейдите в каталог пакета:
   ```bash
   cd /путь/к/MAX-n8n-install-v6
   ```
3. Запустите установщик:
   ```bash
   sudo bash install.sh
   ```
4. Ответьте на вопросы установщика: домен, email для Let's Encrypt, SQL Server, порт, база, SQL-логин и пароль, токен MAX, DNS, параметры TLS SQL и режим общего отчёта. Пароль и токен вводятся скрыто.
5. Установщик проверит DNS домена и TCP-доступность SQL Server, сохранит `.env` с правами `600`, создаст индивидуальный `N8N_ENCRYPTION_KEY`, установит Docker, n8n, Nginx и сертификат Let's Encrypt.
6. Откройте HTTPS-домен и создайте первую учётную запись Owner.
7. В n8n откройте **Settings → n8n API → Create an API key**.
8. Вернитесь в терминал и введите API Key в скрытый запрос. Настройка Credentials, Data Table, workflow и MAX callbacks выполняется автоматически.

Установщик рассчитан на отдельный сервер с прямым пробросом 80/443. Если перед ним уже работает другой reverse proxy, схему сети необходимо отдельно адаптировать.

## Повторный запуск

Если найден `.env`, установщик предложит использовать сохранённые параметры. Пустой ввод сохраняет прежнее значение; новое значение можно ввести вместо него.

Существующий `N8N_ENCRYPTION_KEY` сохраняется. Не удаляйте и не меняйте его для действующей установки: он нужен для расшифровки сохранённых Credentials.

При повторной настройке существующие Credentials с совпадающими именем и типом обновляются.

## TLS SQL Server

TLS включён по умолчанию. При включённом TLS можно отдельно разрешить недоверенный или самоподписанный сертификат (по умолчанию запрещено). Предпочтительно использовать сертификат, которому доверяет система. Разрешение недоверенного сертификата ослабляет проверку сервера. Если SQL Server не использует TLS, выберите `false`. Согласуйте настройки с администратором SQL Server.

## Режим общего отчёта

- `none` — общий отчёт не отправляется, персональные уведомления продолжают работать.
- `chat` — общий отчёт отправляется в групповой чат MAX; нужен ID чата.
- `user` — общий отчёт отправляется ответственному пользователю MAX; нужен ID пользователя.

Если ID не указан, общий отчёт отключается.

## Что настраивается автоматически

- n8n 2.42.6 и MAX community node 1.1.2;
- SQL, MAX и Header Auth Credentials;
- Data Table `report_recipients` с колонками `fio` (string) и `max_user_id` (number);
- импорт workflow `Report СЭМД`;
- подстановка домена организации, Credentials и ID Data Table;
- регистрация MAX callbacks `bot_started` и `message_created`;
- активация workflow и контрольная проверка.

## Действия администратора после установки

1. Откройте **n8n → Data tables → report_recipients**.
2. Заполните только колонку `fio` ФИО врачей в том виде, в котором они будут отправлять его боту (например, `Иванов И.И.`).
3. Сотрудник открывает MAX-бота, нажимает «Начать» и отправляет своё ФИО.
4. Workflow сопоставляет ФИО с таблицей и автоматически записывает MAX `user_id` в `max_user_id`.
5. Не заполняйте `max_user_id` вручную.
6. Проверьте регистрацию тестового сотрудника и выполнение отчётов в 09:00 за предыдущий день и в 15:00 за текущий день.

## Безопасность и резервное копирование

- `.env` содержит SQL-пароль и MAX-токен. Храните его только в защищённом месте.
- Обязательно сохраните `N8N_ENCRYPTION_KEY`: без него зашифрованные Credentials невозможно восстановить.
- Сохраняйте резервные копии Docker volume `n8n_data`.
- Не удаляйте volume `n8n_data` при обновлении или переустановке.
- Не публикуйте `.env`, API Key n8n, токен MAX и SQL-пароль.

## Что не подтверждает установщик

Проверка DNS подтверждает разрешение домена, а TCP-проверка — доступность порта SQL Server. Они не подтверждают SQL-аутентификацию, права `SELECT` и совпадение структуры БД.

До массового запуска проведите пилотную проверку SQL-выборок, обоих расписаний, персональных уведомлений, регистрации MAX `user_id`, выбранного режима общего отчёта и повторного запуска установщика.
