ПАКЕТ MAX + n8n — Report СЭМД (v3)
===================================

НАЗНАЧЕНИЕ
----------
Установка n8n 2.42.6 и workflow «Report СЭМД» для медицинских организаций
с идентичной структурой SQL-базы МИС. Между организациями меняются адрес
SQL Server, порт, имя БД, SQL-учетная запись, домен n8n и MAX-токен.
Предполагается полное совпадение схем, таблиц, имен и типов столбцов,
которые используются исходными SQL-запросами.

ДО УСТАНОВКИ
------------
1. Ubuntu Server 22.04 (рекомендуется отдельная VM).
2. DNS A-запись домена n8n на публичный IP сервера.
3. Входящие TCP 80/443 и исходящий TCP 443.
4. Сетевой доступ VM к SQL Server по TCP 1433 или заданному порту.
5. SQL-логин с минимально необходимыми правами чтения. Не использовать sa.
6. Токен MAX-бота организации.
7. Убедиться, что структура БД соответствует исходной базе проекта.

УСТАНОВКА
---------
1. Скопировать папку MAX-n8n-install-v3 на Ubuntu.
2. Перейти в каталог пакета: cd /путь/к/MAX-n8n-install-v3
3. Запустить: sudo bash install.sh
4. Ответить на вопросы установщика: домен, email, SQL Server, порт, БД,
   SQL-логин/пароль, токен MAX, TLS SQL и режим общего отчета. Пароль и
   токен вводятся скрыто. Не нужно заранее создавать или редактировать .env.
5. Установщик проверит DNS и TCP-порт SQL, сохранит .env (права 600),
   сгенерирует индивидуальный N8N_ENCRYPTION_KEY, установит Docker, n8n,
   Nginx и HTTPS-сертификат Let's Encrypt.
6. Откройте HTTPS-домен, создайте первую учетную запись Owner.
7. Войдите в n8n → Settings → n8n API → Create an API key.
8. Вернитесь в терминал и введите API Key в скрытый запрос. Дальше настройка
   выполняется автоматически.

ПОВТОРНЫЙ ЗАПУСК
----------------
Если найден .env, установщик спросит, использовать ли сохраненные параметры.
При согласии Enter сохраняет текущее значение; можно ввести новое.
Существующий N8N_ENCRYPTION_KEY сохраняется. Не удалять и не менять его
для действующей установки.

TLS SQL SERVER
--------------
TLS по умолчанию включен. При включенном TLS можно отдельно разрешить
недоверенный/самоподписанный сертификат (по умолчанию запрещено). Лучше
использовать сертификат, которому доверяет система. Разрешение недоверенного
сертификата ослабляет проверку сервера. Если SQL Server не использует TLS,
выберите false. Согласуйте значение с администратором SQL Server.

РЕЖИМ ОБЩЕГО ОТЧЕТА
-------------------
none — общий отчет не отправляется, персональные уведомления работают.
chat — общий отчет в групповой чат MAX, нужен ID чата.
user — общий отчет ответственному пользователю MAX, нужен ID пользователя.
Если ID не указан, общий отчет отключается.

АВТОМАТИЧЕСКАЯ НАСТРОЙКА
------------------------
Устанавливается n8n-nodes-max 1.1.2; создаются Credentials SQL, MAX и
Header Auth; Data Table report_recipients (fio string, max_user_id number);
импортируется workflow Report СЭМД; подставляются домен, Credentials и ID
таблицы; регистрируются MAX callbacks bot_started и message_created;
workflow активируется.

ПОСЛЕ УСТАНОВКИ
---------------
1. n8n → Data tables → report_recipients. Заполнить колонку fio ФИО врачей
   в том виде, в котором они будут отправлять его боту (например Иванов И.И.).
2. Сотрудник открывает MAX-бота, нажимает «Начать» и отправляет ФИО.
3. Workflow проверяет ФИО и автоматически записывает MAX user_id.
4. max_user_id вручную не заполнять. Проверить регистрацию тестового
   сотрудника и выполнение отчетов в 09:00 и 15:00.

БЕЗОПАСНОСТЬ И РЕЗЕРВНОЕ КОПИРОВАНИЕ
-----------------------------------
.env содержит SQL-пароль и MAX-токен; хранить его только в защищенном месте.
Сохранить N8N_ENCRYPTION_KEY: без него зашифрованные Credentials не восстановить.
Не удалять Docker volume n8n_data. Таблица получателей создается пустой.

ОГРАНИЧЕНИЯ ПРОВЕРКИ
--------------------
DNS и TCP-проверка подтверждают только разрешение домена и доступность
порта SQL. Они не подтверждают SQL-аутентификацию, права SELECT и совпадение
структуры БД. Это нужно проверить пилотным запуском workflow. До массовой
рассылки проверить: оба расписания, выборки SQL, персональные уведомления,
регистрацию MAX user_id, режим общего отчета и повторный запуск установщика.
