# MAX + n8n — модульный установщик v2

Устанавливает один или оба модуля на общей платформе n8n:
1. **СЭМД** — отчёты и регистрация сотрудников.
2. **VK → MAX** — перенос новых публикаций сообщества VK в групповой чат MAX (текст, фотографии и видео).

## Поддерживаемая ОС
Официально поддерживается Ubuntu Server 22.04 LTS и 24.04 LTS. Другие дистрибутивы в этой версии не заявлены как поддерживаемые.

## Логика установки
- Меню: только СЭМД, только VK → MAX, оба модуля.
- Если обнаружен один работающий контейнер n8n версии **2.42.6**, установщик делает резервную копию данных и добавляет модуль без пересоздания контейнера, без изменения N8N_ENCRYPTION_KEY и без переустановки Docker/n8n. Другие версии и неоднозначная ситуация с несколькими контейнерами безопасно отклоняются.
- Если n8n не найден, устанавливается новая платформа n8n 2.42.6, Nginx и Let's Encrypt.
- Существующие Credentials и workflow не перезаписываются. Уже активный одноимённый workflow пропускается без изменений; неактивный workflow блокирует установку до ручной проверки. Существующие Credentials с теми же именем и типом используются без изменения. Недостающий модуль можно добавить отдельно.
- Community nodes фиксированы по версиям. Автоматическое обновление пакетов не выполняется. Если нужный пакет отсутствует, n8n устанавливает его и один раз перезапускает контейнер для загрузки node-пакета; контейнер не пересоздаётся. Это вызывает короткий перерыв в работе n8n. Если пакет нужной версии уже установлен и загружен, перезапуск не требуется.

## Установка
**Команду screen запускает администратор; сам install.sh screen не создаёт.** Это защищает процесс установки от обрыва SSH/PuTTY.

```bash
sudo apt update
sudo apt install -y git screen
sudo git clone https://github.com/nesterovichvmir/MAX-n8n-install.git /opt/MAX-n8n-install
sudo screen -S max-install bash /opt/MAX-n8n-install/v2/install.sh
```

Если соединение оборвалось, переподключитесь и выполните:
```bash
sudo screen -r max-install
```
Для временного отсоединения нажмите Ctrl+A, затем D.

Для новой установки откройте HTTPS-домен, создайте Owner, затем Settings → n8n API → Create an API key. Вставьте ключ в скрытый запрос терминала. Если n8n предлагает выбрать API scopes, разрешите просмотр/создание/изменение workflow, просмотр/создание Credentials, просмотр/установку community packages, просмотр/создание Data Tables и просмотр/создание колонок Data Tables.

## Требования VK → MAX
- Публичный HTTPS URL n8n и доступный из интернета webhook.
- Токен сообщества VK и строка подтверждения Callback API (Confirmation String), заданная в настройках сообщества; установщик запросит оба значения. API Version задаётся как 5.199. Если в VK настроен Secret Key, его также можно ввести.
- После установки откройте workflow `VK → MAX (v2)`, узел `VK Community Trigger`, скопируйте Production URL. В VK добавьте отдельный Callback API сервер, вставьте URL и подтвердите адрес. Не меняйте существующий production-сервер.
- ОБЯЗАТЕЛЬНО: во вкладке `Типы событий` нового сервера включите `Записи на стене → Добавление` (`wall_post_new`). Одного подтверждения URL недостаточно: без включённого события VK не отправляет новые публикации.
- Токен MAX-бота и получатель: личный MAX User ID либо числовой ID группового чата. Для личных сообщений пользователь должен открыть диалог с ботом; для групповой отправки бот должен быть добавлен в чат.
- Интернет на сервере.
- Для видео yt-dlp устанавливается на Ubuntu-хост (если его ещё нет); n8n подключается к нему по SSH через Docker gateway. Отдельный пользователь `n8n-vk` без sudo создаётся только при первой установке VK. Пароль сохраняется в `/root/.n8n-vk-ssh-password`; существующий пароль повторно не сбрасывается. Установщик проверяет TCP-доступность SSH из контейнера n8n. SSH Credential хранится в n8n.
- Видео загружается в качестве до 1080p, как в исходном workflow.

Три JavaScript Code nodes исходного VK workflow сохраняются без изменения кода. Установщик заменяет Credentials, получателя MAX (личный `user_id` или групповой `chat_id`) в трёх узлах отправки и исправляет тело запроса текстовой ветви. При импорте поле `active` удаляется из JSON, так как в n8n 2.42.6 оно доступно только для чтения; затем workflow активируется отдельным API-запросом.

## Требования СЭМД
- Структура SQL Server базы МИС должна совпадать с исходным workflow.
- TCP-доступ к SQL Server (обычно порт 1433), SQL-логин с минимально необходимыми правами, токен MAX.
- Создаётся/проверяется пустая Data Table `report_recipients` с колонками `fio` (string) и `max_user_id` (number). Администратор вручную заполняет только `fio`; MAX user_id бот получает автоматически.
- Общий отчёт: `none`, `chat` или `user`. Установщик регистрирует в MAX только событие `bot_started`; после его получения workflow самостоятельно регистрирует `message_created`, как предусмотрено исходной схемой.

## Безопасность и ограничения
- Резервная копия существующей установки: `/var/backups/max-n8n-v2`. При `N8N_ENCRYPTION_KEY` в переменных контейнера рядом сохраняется файл `.key`; храните его вместе с архивом и отдельно защитите. Если n8n использует внешнюю БД (например PostgreSQL), установщик остановится до создания резервной копии — сначала сделайте backup этой БД самостоятельно.
- Не меняйте и не удаляйте N8N_ENCRYPTION_KEY.
- Существующие Credentials с теми же именем и типом установщик повторно использует без изменения. Если токен или пароль нужно заменить, обновите соответствующий Credential вручную в n8n — автоматическая перезапись секретов запрещена.
- Не публикуйте API Key n8n, токены VK/MAX, SQL-пароль, файл резервного N8N_ENCRYPTION_KEY и архив резервной копии.
- Установка VK добавляет SSH Match rule для разрешения парольного входа только выделенному пользователю n8n-vk. Пользователь не имеет sudo.
- Проверка TCP SQL не подтверждает SQL-аутентификацию, права или совпадение структуры БД.
- После установки обязательно протестируйте публикации VK с текстом, фото и видео.
- При существующем n8n установщик не меняет Docker Compose, Nginx и параметры контейнера. Если в текущем n8n запрещена установка community nodes, настройте это отдельно до запуска.

## Проверка пакета (для разработчиков)
**Администратору, который устанавливает систему, выполнять эти команды не нужно.** Статическая проверка проводится при подготовке выпуска и автоматически в GitHub Actions. Она не подключается к серверу и ничего в нём не меняет.

Для ручной проверки пакета разработчиком:

```bash
cd /opt/MAX-n8n-install/v2
python3 check_package.py
python3 -m py_compile configure.py check_package.py
bash -n install.sh
```

Статическая проверка не заменяет функциональное тестирование на отдельной тестовой VM.

## Состав
- `install.sh` — выбор модулей, обнаружение n8n, backup и подготовка ОС.
- `configure.py` — настройка n8n API, Credentials и импорт workflow.
- `check_package.py` — статическая проверка структуры пакета и неизменности Code nodes.
- `workflow.vk.template.json` — шаблон VK → MAX.
- `workflow.semd.template.json` — шаблон СЭМД.
- `docker-compose.yml` — только для новой установки.
- `nginx-n8n.conf.template` — reverse proxy для новой установки.
