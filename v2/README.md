# MAX + n8n — модульный установщик v2

Установщик разворачивает общую платформу n8n и подключает выбранные модули:

1. **СЭМД** — отчёты о неподписанных СЭМД и регистрация сотрудников через MAX.
2. **VK → MAX** — пересылка новых публикаций сообщества ВКонтакте в групповой чат MAX (текст, фотографии и видео).

## Полное руководство администратора

**[Открыть полное руководство MAX + n8n v2](ADMIN_GUIDE_V2.md)**

Руководство рассчитано на администратора, который впервые устанавливает систему. В нём описаны общая установка, выбор модулей, создание API Key, отдельная настройка СЭМД и VK → MAX.

## Поддерживаемая ОС и версии

- Ubuntu Server 22.04 LTS или 24.04 LTS.
- n8n 2.42.6.
- Для новой установки установщик разворачивает n8n 2.42.6.
- Для существующего n8n установщик добавляет выбранные модули, не пересоздавая контейнер и не меняя N8N_ENCRYPTION_KEY.

## Выбор модулей

В меню установщика:

- **1** — только СЭМД;
- **2** — только VK → MAX;
- **3** — СЭМД + VK → MAX.

При выборе одного модуля запрашиваются только его параметры. При выборе нескольких модулей перед каждым набором вопросов выводится название и порядковый номер, например **«МОДУЛЬ 1 ИЗ 2 — СЭМД»** и **«МОДУЛЬ 2 ИЗ 2 — VK → MAX»**. Каждый запрос также помечен названием текущего модуля.

## Основные особенности

- Если найден один работающий контейнер n8n версии 2.42.6, установщик создаёт резервную копию и добавляет выбранные модули без пересоздания контейнера.
- Публичный URL существующего n8n автоматически определяется по параметрам контейнера, если они доступны.
- API Key сохраняется в `/root/.n8n-api-key` с правами доступа 600 и повторно используется, пока действителен.
- Существующие Credentials и workflow не перезаписываются. Уже активный одноимённый workflow пропускается; неактивный одноимённый workflow требует ручной проверки.
- Community nodes устанавливаются в зафиксированных версиях. Если нужный пакет отсутствует, n8n перезапускается для его загрузки; контейнер не пересоздаётся.
- Для видео VK → MAX используется standalone `yt-dlp`, не требующий замены системного Python.
- Резервные копии существующего n8n сохраняются в `/var/backups/max-n8n-v2`.

## Запуск

Команду `screen` запускает администратор:

```bash
sudo apt update
sudo apt install -y git screen
sudo git clone https://github.com/nesterovichvmir/MAX-n8n-install.git /opt/MAX-n8n-install
sudo screen -S max-install bash /opt/MAX-n8n-install/v2/install.sh
```

Если SSH-соединение оборвалось, переподключитесь и вернитесь в сеанс:

```bash
sudo screen -r max-install
```

Для временного отсоединения от сеанса нажмите Ctrl+A, затем D.

## Требования к модулям

### СЭМД

- SQL Server доступен с сервера установки по TCP.
- Структура базы МИС соответствует исходному workflow.
- После установки администратор вручную заполняет ФИО сотрудников в Data Table `report_recipients`; MAX user ID регистрируется автоматически.
- Режим общего отчёта: `none`, `chat` или `user`.

### VK → MAX

- Нужны токен сообщества VK, Confirmation String, токен MAX-бота и числовой ID группового чата MAX.
- MAX-бот должен быть добавлен в групповой чат и назначен администратором.
- В VK создаётся Callback API сервер с Production URL из узла VK Community Trigger.
- В настройках сервера включается событие **Типы событий → Записи на стене → Добавление**.
- Личные ID пользователей MAX не поддерживаются.

## Безопасность

- Не меняйте и не удаляйте N8N_ENCRYPTION_KEY.
- Существующие Credentials с теми же именем и типом повторно используются без изменения.
- Не публикуйте API Key n8n, токены VK/MAX, SQL-пароли и резервные копии.
- Если n8n использует внешнюю БД, установщик остановится до резервного копирования этой БД. Создайте её backup отдельно.

## Структура пакета

- `install.sh` — выбор модулей, обнаружение n8n, резервное копирование и подготовка ОС.
- `configure.py` — создание Credentials, настройка Data Table и импорт workflow.
- `workflow.semd.template.json` — шаблон СЭМД.
- `workflow.vk.template.json` — шаблон VK → MAX.
- `check_package.py` — статическая проверка пакета для сопровождающего.
- `ADMIN_GUIDE_V2.md` — полное руководство администратора.
